# Protected Preview verification without test analytics

Use the exact immutable Preview URL and source SHA in the current readiness report, not a moving branch alias. A Preview build and local fixture tests are separate evidence. Never disable Vercel Deployment Protection, export an authenticated browser profile, expose a bypass secret, or promote a deployment to make tests easier.

## Preview-only verification surface

`VERCEL_ENV=preview`, supplied by Vercel, prevents the Analytics component from mounting on both static and dynamic Preview pages. Production analytics remains enabled. No collection endpoint is contacted to prove suppression. Regression tests reject any outbound script/event request and verify production builds retain analytics while returning HTTP 404 for the verification routes. No deployment protection or authentication setting is changed.

After confirming the exact source SHA and normal build in Vercel, open the protected immutable Preview at `/preview-check`. Its dynamic Node function displays a request-time, allowlisted process-version record. The header buttons make ordinary same-origin GETs to `/profile`, an observed hashed script, or `/hall/atrium`; they display only public security/cache headers. They never export cookies, tokens, redirect values, environment objects or arbitrary exception strings. A Preview-only `knightbite.preview_function_runtime` log from the menu loader independently records that function process's versions. These are observations of particular invocations, not an attestation of every instance or future managed patch.

The protected `/preview-check/unavailable` page explicitly labels a controlled null-menu/date-boundary rendering: `2026-09-11T00:30:00Z` becomes September 10 at Rutgers. It calls the same unavailable view without food or provider requests. It is hosted component evidence, **not a manufactured live-provider failure**. Normal hall routes, caches and requested-date behavior are unchanged.

**Build approved source under Production; never promote a Preview-built artifact to Production.** Static pages retain build-time environment behavior, and promotion does not rebuild them. A normal Production build must have analytics enabled and both diagnostic routes unavailable. This is why a Preview is only a recovery-source reference, not a production rollback artifact. [Vercel system variables](https://vercel.com/docs/environment-variables/system-environment-variables)

## Authenticated manual browser procedure

1. For a source-verified Preview containing the suppression above, use the maintainer's normally authenticated browser and open `/preview-check`; no local request blocker is needed because the SDK is omitted. For older Previews or separately approved Production verification, use the following blocking procedure. Use the maintainer's normally authenticated desktop browser. In a blank tab, open Developer Tools → Network request blocking **before** navigating to KnightBite. Enable local blocking for `*/_vercel/insights/*`, `*va.vercel-scripts.com/*`, `*vitals.vercel-insights.com/*`, and any additional collector/script endpoint identified by the reviewed SDK configuration. Keep the Network log open. Do not change project settings, install an unreviewed extension or copy authentication material. If the browser cannot block requests before navigation, stop this smoke and use the isolated harness below.
2. Open the immutable Preview `/profile` through normal Vercel authentication. Verify the deployment's full Git SHA in Vercel first. Inspect the profile response headers: CSP (no production `unsafe-eval`), `frame-ancestors 'none'`, DENY, nosniff, referrer and permissions policies. Inspect a normal hashed JS/CSS response for immutable caching. Record only these public headers, not cookies, authorization headers or SSO redirect values. Confirm blocked analytics requests have no delivered response; record the distinction between a blocked script and a tested SDK transport.
3. Use ordinary navigation to the homepage and Atrium once, without cache-busting, crafted URLs, upstream probes or repeated load tests. Record the requested Rutgers calendar date and observed menu status. A successful menu must show that date, plausible returned portions and only returned retrieval times. A failure must settle within the existing display deadline, show the unavailable message and no food cards or backup/sample label. A timeout/unknown status does not establish a closure or absent Rutgers publication. If the live source happens to succeed, do not manufacture a provider failure on the shared host: use the exact-source offline failure test below and identify it as such.
4. If a real menu is returned, compare one item/portion against already available sanitized source evidence or the ordinary displayed source; do not certify nutrition/labels from appearance alone. Add two distinct available portions, verify quantities and per-field known/unknown totals, use increment/decrement/remove, then open the plate drawer with the keyboard. Check Tab/Shift-Tab through every control, Escape, focus return and temporary plate reset after reload. Missing values must not become verified zero. Do not invent test foods on the hosted application.
5. At 375 px and 320 px, use the hall's Explore/Menu/My plate/Halls controls, open and close the plate, and return to hall selection. Check that navigation settles and the document does not scroll horizontally (the designed Atrium map can have its own horizontal region). Test 200% browser zoom separately from CSS text enlargement.
6. Record exact browser/version, date/time, source SHA, immutable URL, successful/failed assertions, console errors and blocked analytics endpoints. Stop on an unexpected unblocked collector request. Clear only the temporary test preferences using KnightBite's own clear-local-data control. Do not erase an existing user's preferences without consent.

For spoken accessibility evidence, follow [Safari/VoiceOver QA](ACCESSIBILITY_QA.md) with a named tester. Chromium/WebKit automation, an accessibility tree and screenshots do not verify VoiceOver announcements.

## Repeatable offline failure and nutrition checks

On the exact source revision, run `npm ci`, `npm run check` on both runtimes specified by [runtime policy](RUNTIME_POLICY.md). The isolated production build uses the normal analytics-enabled bundle and synthetic/sanitized provider transports. All browser analytics are intercepted locally; no provider requests or events leave the test harness. Do not publish its fixture-tested build.

The dedicated `playwright.unavailable.config.ts` run makes Atrium return HTTP 503 and sets the **test server** clock to `2026-09-09T00:30:00Z`, which is September 8 at Rutgers. It checks the dated unavailable output, no food/retrieval timestamp, empty plate drawer and mobile return to a homepage with only two confirmed menus. Production contains no usable route, query parameter or configuration switch for this scenario. The distinct Preview-only controlled view above does not exercise provider ingestion. Unit tests separately control the 1.1-second homepage deadline and 15-second hall deadline, late promise results, provider exceptions/null results and no mock fallback.

The main browser suite covers returned sanitized Atrium items, distinct 120/240-kcal rice portions, unknown/zero/partial nutrition, plate controls and keyboard focus, preference storage failures and mobile navigation. Those are arithmetic/conservation regressions, not an independent assurance of Rutgers' nutritional data or allergen safety.

The platform-script test may replay an identified, previously captured public Vercel script locally with `KNIGHTBITE_ANALYTICS_SCRIPT_FIXTURE`; the script and every collector request are fulfilled locally. A passing replay does not verify changing remote scripts or deployed edge headers.

## Tooling boundaries

The authenticated in-app browser has no documented request interception. Preview source-level suppression makes normal hosted testing possible without exporting authentication or changing Production analytics. An older Preview or Production artifact still requires a browser with local request blocking before navigation. Isolated Playwright tests cannot substitute for authenticated hosted observations, and an accessibility tree cannot substitute for VoiceOver.
