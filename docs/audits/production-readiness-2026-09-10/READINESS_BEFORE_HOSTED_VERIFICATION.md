## Runtime decision

The former `>=24.21.0` engine constraint copied the preferred latest LTS/tooling pin in remediation commit `8316152`; no repository requirement identified an API or CVE fixed precisely at that minimum. Vercel's official policy and current selector offer managed major versions **24.x, 22.x, 20.x**, with no independently selectable function patch. Installing a newer build binary would not prove a newer function runtime.

The current application supports the reviewed **Node >=24.19.0 <25** floor, while `.nvmrc` remains **24.21.0**. The same required `KnightBite release verification` job now executes its complete gate on **both** versions; there is no alternate optional check or status bypass. `prebuild` rejects Node/component versions below the reviewed floor and emits public commit/build/native-library versions. It does not attest the function runtime.

This decision follows the official Node July security boundary (24.18.1), installed dependency engine compatibility and the input/API prerequisites of newer OpenSSL/Undici advisories. **The 24.19.0 bundle includes versions affected by later component advisories**; the reviewed app does not use their required WebSocket, optional interceptor/custom TLS-pool or OpenSSL API surfaces. This is not a declaration that all bundled code or Vercel internals are fully patched. Details, primary sources and conditions requiring renewed review: [runtime policy](../../RUNTIME_POLICY.md), [advisory inventory](runtime-evidence/undici-advisories.json). Prefer Vercel's newer patched runtime when available; a new reachable unpatched issue blocks release.
